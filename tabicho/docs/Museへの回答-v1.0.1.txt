■ 必須修正
==================================================
M-1　appsscript.json に Maps 用スコープが無い　→ 対応済み（方法を変えた）
・ご指摘のとおり、マニフェストでスコープを明示すると自動判定が効かなくなる
・ただし Apps Script の Maps サービス（DirectionFinder／Geocoder）に対応する
　「https://www.googleapis.com/auth/maps」というスコープが存在するかを、こちらの環境から
　Google のリファレンスで確認できなかった（存在しないスコープを書くと、承認そのものが失敗するおそれがある）
・そこで oauthScopes の項目自体を外し、Maps を含む全ての権限を Apps Script の自動判定に任せる形にした
　（スポット帳・家計簿・ほしいもの帳と同じ形。webapp の設定〈実行ユーザー：自分／アクセス：自分のみ〉は残した）
・実機での確認（setupTabicho の承認画面、設定の「接続テスト」で 経路（Maps）が ✅）はデプロイ時に必要。U-1 に含む

■ 注意・運用
==================================================
N-1　年跨ぎの引落日の祝日　→ 元から対応済み。念のため明示化
・家計簿 GAS v7.0 の getJapaneseHolidays は「指定年の前年1月〜翌年12月」を返す
　（年パラメータなしなら今年基準）。12月利用→翌1月引落でも翌年の祝日は入っていた
・念のため、送る明細の最も新しい年を loadAll の year に渡すようにした
　（例：2027年1月に、前年12月の旅の明細を送る場合も 2026〜2028 の祝日が入る）

N-2　割り勘分の収入行の budgetCat が空欄　→ 対応済み
・家計簿の evaluateEntry と同じ規則（大分類が 純収入・精算・移動・貯蓄移動・投資移動 なら、
　用途＝カテゴリー名、予算区分＝大分類）で、送信時に入れるようにした
　（割り勘 → 用途「割り勘」／予算区分「精算・移動」）。区分の固定（catLock）は付けない

N-3　実効レートの分母は自分が払った外貨現金のみ　→ 意図どおり（画面に注記を追加）
・実効レートは「自分の両替」で手に入れた外貨の、自分にとっての1単位あたりの円の重さ。
　他のメンバーが払った外貨現金はその人自身の両替から出ているので、自分の分母に入れると
　逆にずれる
・他の人が払った支出の自分の負担分は、支出ごとのレートで精算通貨（円）に換算され、
　精算（円の送金）で清算されるので、家計簿へもその円額で送る
・想定外になるのは「自分の両替した現金を他の人が持って払った」場合。その時は、払った人を
　自分にして入力してもらう運用とする。この考え方を両替・家計簿の画面に一文で注記した

N-4（T-7）「絶対行きたい」タグの追加が必要　→ そのとおり。デプロイ手順 §8-6 に記載済み
