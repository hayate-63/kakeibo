3. 「入力中」の判定を共通化（isEditingInput）
==================================================
・src/js/99_main.js：isEditingInput(el) を新設。INPUT・TEXTAREA・SELECT のうち、
　checkbox／radio／button／submit／reset／file／range／color を除いたものを「入力中」とする
・softRender() と focusout の 300ms 後の判定の両方がこれを使う。
　テキスト欄からチェックボックスへ直接移った時も、保留していた描き直しが走る（v204.e2e.js で確認）
・isTyping()（1分ごとの描き直し・画面に戻った時の描き直し）：【揃えた】
　isTyping() ＝ isEditingInput(今の欄) かつ モーダルが開いていない。
　変わるのは「チェックボックス等にフォーカスがある時も定期の描き直しが走るようになる」点だけ。
　チェックボックスは押した時点で保存済みで、描き直しで失うものが無いため、意味はずれない
　（呼び出し側はもともと「モーダルが開いていない」も別に確かめているので、その条件は今まで通り）

5. 持ち物の追加欄（.pack-new）の下書きを守る
==================================================
・src/js/08_shiori.js：
　- 追加欄に data-input="packDraft"。打った内容を S.ui.packDraft に保持
　- 下書きのキーは「旅ID｜カテゴリー」（むぎの注意どおり、別の旅を開いても前の旅の下書きは出ない）
　- renderPacking() で各追加欄の value に下書きを戻す
　- ACT.packAdd で追加できたら、その旅・カテゴリーの下書きを消す
　- 下書きは画面の中だけ（端末には保存しない。再読み込みで消える）
・確認（v204.e2e.js）：入力中に softRender → キーボードを閉じる（フォーカスを外す）→ 描き直し後も文字が残る、
　追加で欄が空になる、別の旅の追加欄は空

6. 【K-4 クローズ】動画の日付にファイルの更新日時（file.lastModified）
==================================================
・src/js/14_media.js registerMedia()：日付の決め方
　1. 追加時の手動指定（q.date）→ dateSource: 'manual'
　2. Drive の撮影日時（EXIF）→ 'exif'
　3. 動画で、q.lastModified が正しい数値の時 → 旅の現地の時刻（tripTz）に直した日付・日時。
　　 takenAt にも YYYY-MM-DDTHH:mm:ss で入れる（時系列の並びに使う）→ 'file'
　4. どれも無ければ 旅の現地の今日 → 'upload'
　変換は新しい fileTimeInTrip(trip, ms)（既存の tzParts を使用）。写真は今まで通り（EXIF → アップロード日）
・拡大画面（openMediaViewer）の日付の由来：'file' は「ファイル更新日時（変更できます）」と表示
・手動での修正は今まで通り（日付を変えると 'manual'）。iPhone でファイルを選んだ時刻が更新日時になってしまう場合は、ここで直す
・q.lastModified はキューを作る時に既に保持しているので、保存の追加は無し
・確認（v204.e2e.js）：日本 11/26 12:15 の更新日時 → ハワイの旅では 2026-11-25・17:15:09・'file'。
　手動が優先、写真と更新日時なしの動画は 'upload'
