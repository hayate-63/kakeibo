3. 設計メモとの対応
==================================================
【Q1 ステータス】
・検討中（日付なし）→ 計画中（日付あり）→ 確定 → 旅行中（今日が期間内）→ 精算・記録中（期間後）→ 完了、＋中止
・手動は「中止」「完了」だけ。検討中は日付なしで作れば自動でそうなる。日付を入れると計画中へ
・「確定」の条件は設計メモに無かったので決めた（§4 T-1）

【Q2・Q3 範囲とタブ】
・5タブ：ホーム／しおり／ドライブ／お金／記録。設定は右上の歯車
・ドライブは独立タブ。車を使わない旅では「移動」タブとして次の駅・空港・港を出す

【Q4 旅の基本項目】
・必須：タイトル／日程（未定可）／モード（しおり・リスト）／メンバー（プリセットあり）
・任意：行き先エリア／出発地（既定＝自宅・亀山）／予算／主な乗り物（車・電車・飛行機・フェリーの複数選択）／代表絵文字／メモ
・日帰りは開始日＝終了日から自動判定。精算通貨も旅ごとに持つ（多通貨対応）

【しおり／リスト・混合表示】
・地図（上）＋工程（下）の配置。日時ありのアイテム＝工程ゾーン（●と線＋絵文字）、日時なし＝リストゾーン（折り畳み可）
・日時を入れれば工程へ、外せばリストへ自動で移る。しおりモードでも未定はリスト、リストモードでも日時が決まったものは工程表示
・絵文字の連続移動：各区間＝そのアイテムの滞在＋移動の時間枠。経過割合で線上の位置を決め、滞在中も動く（20秒ごと更新）。線の通過済み部分は色が付く
・モード切替：しおり→リストは時刻を保持したまま隠す。リスト→しおりは「未配置」に入り、保持していた時刻はワンタップ（全件 or 1件ずつ）で戻せる。どちらの向きでもデータは失われない

【リストモードの表示（基本＋追加8項目）】
・期間中の営業時間／現在地からの距離・所要時間（乗り物は地図横の設定ボタン→モーダル）
・①行ける日バッジ ②今日の営業・閉店まであと◯時間 ③優先度 ④近くのスポットとの距離・所要時間 ⑤滞在・料金目安 ⑥駐車場（車）・最寄り駅（電車）⑦その日の天気 ⑧「行った」ボタン
・並び替え：距離順／閉店が近い順／優先度順。座標なしは「座標なし」表示で残す
・「行った」を押したスポットは下の「行った済み」へ移り、そこで取り消せば元に戻る（スポット帳への書き戻し・取り消しも同時）
・乗り物モーダル：車（高速・有料道路を使うかの指定、高速料金の概算）、電車（運賃）、飛行機・フェリー（概算）

【金額入力の共通ルール】
・金額入力のある全箇所（予約・支出・給油）を同じ部品にした：割り勘する人のチェック／「1人で払う」／1人あたりのその場表示（端数は払った人）
・「電卓モード」と「キーボード」を入力欄ごとにその場で切替（最後に使った方を覚える）
・為替計算機も支出の入力画面から開け、計算結果をそのまま金額へ反映できる

【Q5 しおり詳細】
・アイテムは スポット／固定枠／移動 の3種。開始＋滞在、終了は自動
・次の開始は「前の終了＋移動時間」で自動提案、手動で上書き可。移動時間は経路から自動計算（5分単位で切り上げ）、手動上書き可
・固定枠はロックでき、前が延びてもずれない。間に合わない／重なり／営業時間外／定休日／要予約で未予約 に警告バッジ
・日の切替は上部の「1日目／2日目」タブ

【Q6 スポット帳連携】§5 に詳細
・参照方式（スポットIDで参照し、名前・座標は開くたびにスポット帳から最新）。削除されたら「スポット帳で削除済み」で残し、名前は追加時点の控えで出す
・「行った」は即時書き戻し、取り消しも即時。失敗したら旅帳に記録したまま次回再送
・旅帳で手入力したスポットは「スポット帳にも登録する」でスポット帳へ登録

【Q7 予約・持ち物・ドライブ】
・予約：種別／タイトル／日時／場所（スポット参照可）／金額／予約番号／URL／メモ／状態（要予約・予約済・キャンセル）
　時刻のある予約はしおりに🔒固定枠として自動で入る。金額はお金タブに「事前支払い」として自動で入る（二重入力なし）
　「要予約」なのに予約が無いものはホームに件数で警告。カレンダー登録は予約ごとのボタン式（登録済みの印・二重登録の確認）
・持ち物：6カテゴリー、テンプレート（日帰り／1泊／2泊以上 × 車旅か、＋乗り物別）から自動生成＋自由追加、進捗％、誰の荷物か
・ドライブ：次の目的地を大きく、出発カウントダウン（次の開始 − 所要時間 − 余裕。余裕の既定10分・設定可）、ナビ起動、
　出発・到着メーターの記録、給油の記録（お金タブへ流れる）、スポットごとの駐車場メモ。愛車保全への連携は入れていない

【Q8 お金・精算】
・支出：日付／内容／カテゴリー（宿・交通・食費・入場体験・土産・給油・その他）／金額／払った人／割り勘対象／支払状態（支払済・現地で払う予定）／支払方法／メモ
・端数は払った人が負担。精算は 払った合計／負担合計／差額 → 送金リスト（受け取り最大の人へ、払う側を大きい順に。n人で最大 n−1回）
・各送金は展開して内訳（払う側の負担内訳・自分の立替の相殺・受け取る側の立替内訳）まで見られる
・実支払額・実受取額（通貨も選べる）を入れると、端数調整と残額（実受取額ベース）を表示
・精算済みチェックは送金ごと。チェック後に支出が変わったらリセットし「再計算しました」と出す
・予算：総額に対する実績・残り・カテゴリー別小計、1人あたり
・家計簿連携：自分の負担分だけを明細ごとに送る。自分がカードで払った分は「支出＝引落額（全額）」＋「収入＝割り勘分」の2本。送信済みの印と二重送信防止（§5）

【多通貨】
・旅ごとの精算通貨、支出ごとの通貨とレート（自動取得・手で上書き可）、集計・精算は精算通貨へ換算
・実効レート＝（両替で払った円 − 戻して得た円 − 繰越分×取得レート）÷ 使った外貨現金。設計メモの台湾ドルの例（5.267円、600TWD → 3,160円）で一致を確認
・戻し両替を入れるまで外貨現金の家計簿送信は止める（旅の途中は両替レートで暫定表示）。次回用に残す場合は取得レートで確定し、残高を繰越として表示
・カード払いの外貨はカード明細の円額（引落額）を使う
・為替計算機：お金タブ上部に常設。現在地から国→通貨を判定し、市場レートで円換算

【Q9 記録】
・日ごとのメモ／旅全体の★と一言感想／代表写真のリンク／自動まとめ（総額・1人あたり・総走行距離・行ったスポット数・日数）／この旅で行ったスポット一覧（後から編集可）
・「記録完了」チェック。精算の全件完了と揃ったらホームに「完了にできます」→ 押すと完了（完了は手動のまま）

【Q10 行き先提案】
・ホームの「行き先を探す」。条件：いつ頃（勤務カレンダーから連休を検出）／日数／メンバー／予算／気分（スポット帳のタグ）
・スポット帳の「行きたい」をエリアで束ね、自宅（亀山）からの片道時間で日数に合う範囲に絞り、「絶対行きたい」を含むエリアを優先
・候補日に全部定休のスポットは落とす。季節タグ（春夏秋冬・月・桜・紅葉など）が時期に合わないものは順位を下げる
・3案それぞれに エリア名／核になるスポット3〜5件／モデルコース（1日目・2日目の流れ）／概算費用（交通＋入場＋食費＋宿）／必要日数
・案をタップすると「検討中」の旅が作られ、スポットがリストモードで入る

4. 実装で決めたこと（要確認）
==================================================
設計メモに書かれていなかった点や、他アプリの作りに合わせて変えた点。違っていれば直します。

T-1　「確定」の条件：日付があり、「要予約」が0件で、「予約済」が1件以上
　　→ 予約の無い日帰り旅は出発日まで「計画中」のまま
T-2　しおり→リストの切替で、固定枠と予約（日時が決まっているもの）は工程に残す（時刻を隠すのはそれ以外）
T-3　訪問の評価：設計メモは「★1〜5」だが、スポット帳 v3.1 の訪問記録が 😫😞😐😋🤩 の5段階（必須）なので、それに合わせた
　　（旅全体の評価は★のまま）
T-4　「行った」ボタン：スポット帳は評価が必須のため、押すと 訪問日＋評価 の画面が出て、顔をタップした時点で保存
　　（スポット帳の［行った！］と同じ操作。設計メモの「その場で押せる」から1タップ増えている）
T-5　旅帳からの「行った」の取り消し：スポット帳で写真・何を・金額などを書き足した訪問記録は取り消さない（思い出を消さないため）。写真はどの場合も消さない
T-6　営業時間：スポット帳に無いので、スポットの place_id から Google Places（New）で取る。旅に入っているスポットだけ・1日1回・端末にも保存
　　→ Places の Pro 料金枠を使う（個人利用なら無料枠内の見込み）。APIキーはスポット帳と同じものを旅帳GASにも入れる
T-7　優先度「絶対行きたい」：スポット帳に項目が無いので、スポット帳のタグ「絶対行きたい」で表す（スポット帳の tags タブに1行足すだけ）
T-8　滞在目安・料金目安・駐車場・最寄り駅：スポット帳に無いので、旅帳のアイテムごとに入れる
T-9　スポットの「エリア」：スポット帳の 地域タグ → 市区町村 → 都道府県 の順で決める
T-10　家計簿へ送る明細：支出は用途「イベント・旅行・レジャー」／予算区分「特別費・レジャー」で区分を固定（catLock）。
　　割り勘分の収入はカテゴリー「割り勘」のまま家計簿の判定に任せる。「現地で払う予定」の支出は送らない。
　　他の人が払った分の自分の負担は、カテゴリー「その他（支出）」で送る（設定で変更可）
T-11　支払方法の初期値：家計簿 v7.0 のカテゴリー名に合わせた（現金＝その他（支出）、カードは三井住友ゴールド(NL)・Olive クレジット・PayPayカード・Amazonマスター・mercard・ガソリン代）。給油の既定は「ガソリン代」
T-12　連休の検出：家計簿の給与計算と同じく、メインのカレンダーの予定のうち残業時間管理ブックの「勤務マスタ」にある勤務名だけを勤務とする。
　　夜勤明けの日は休みに数えない（既定。設定で変更可）。勤務マスタ未設定なら土日祝で判定
T-13　行き先提案の片道時間の範囲：日帰り 2.5時間以内／1泊 45分〜5時間／2泊以上 1.5〜10時間（3案に満たない時は少し広げ、その旨を表示）
T-14　行き先提案の概算費用：燃費15km/L、ガソリン170円/L、食費1食1,500円、宿1泊10,000円（いずれも1人あたり・設定で変更可）、高速は距離からの概算
T-15　高速料金：普通車の概算（有料区間の距離×24.6円＋150円）。ETC割引は含まない
T-16　旅帳 GAS の公開範囲：「自分のみ」（画面も GAS から配信するため PIN 不要）。スポット帳・家計簿は今まで通り「全員＋PIN」
T-17　データの持ち方：旅1件を1行（JSON）で保存。他の端末で先に更新されていたら、どちらを残すか選ぶ画面を出す。端末にも保存するので電波が無くても見られ、つながった時に送る
T-18　天気は Open-Meteo、為替は open.er-api.com（どちらもキー不要）。地図は OpenStreetMap

5. 他アプリとの連携
==================================================
【スポット帳 GAS v3.1】変更なし
・使う API：getAll／addVisit／updateVisit／deleteVisit／addSpot／ping
・「行った」は訪問記録（visits）に入り、スポットの行った／行きたいはスポット帳が訪問記録から自動で決める
・訪問記録に旅の列が無いので、旅帳が自分で作った visit_id を覚えて対応させる。旅帳で編集すると同じ訪問記録を書き換え、スポット帳だけで扱う項目（何を・金額・写真・また行きたいか）は残す
・スポット帳で編集・削除された訪問記録は、次に旅帳を開いた時に取り込む
・旅帳で手入力したスポットは addSpot で登録（メモに「旅帳から登録」、優先度が絶対なら「絶対行きたい」タグ）

【家計簿 GAS v7.0】処理の変更なし（版表記だけ v7.1 にそろえた）
・ほしいもの帳 v1.0.1 と同じ方式：loadAll で明細と rev を読む → 旅帳の明細を足す → 明細一式を baseRev 付きで保存
・旅帳の明細には src="tabicho"、srcRef（旅と明細の目印）を付け、同じ明細は二度入らない
・ほしいもの帳と同じ守り：明細が0件で返ってきたら書かない／件数チェック／支払方法が家計簿の有効なマスタに無ければ送らない
・引落日・引落月・大分類なども家計簿の evaluateEntry と同じ計算（祝日の翌営業日調整つき）で入れて送る
・別の端末が先に保存していたら読み直して再送。保存前の10世代バックアップは家計簿GASが今まで通り取る

【家計簿アプリ v7.1】表示だけ変更
・旅帳から送った明細（src="tabicho"）に水色の「🧳旅帳」の印。ほしいもの帳の明細は今まで通り紫の「🛍️ほしいもの帳」
・明細の詳細に「🧳 旅帳（区分を固定）」「🧳 旅帳から登録（自分の負担分）」
・明細CSVの照合画面で、区分固定の明細の呼び名を「ほしいもの帳・旅帳」に（旅帳のカード払いも照合に出てくるため）
・データ形式・保存処理は v7.0 と同じ

【ほしいもの帳】変更なし（家計簿連携の手本として参照のみ）

　家計簿（PIN違い・保存番号の食い違い時の再送・他端末の明細を消さない・二重送信防止・引落日 11/30→12/28（土曜を翌営業日へ）・0件ガード・無効カテゴリー）／
　スポット帳（エリアと優先度の変換・評価なしを送らない・写真と金額を残した編集・取り消しの可否・写真を消さない指定・手入力スポットの登録・営業時間の変換（定休・日をまたぐ営業）・PIN違い）　→ 全て PASS

　予約が固定枠に入る → 持ち物 → ドライブ → 支出 → 精算と内訳 → 家計簿送信 → 記録 → 設定 → 行き先提案3案　→ エラーなし

8. デプロイの順番
==================================================
1. 旅帳：新しい GAS プロジェクトに gas-v1.0.txt（Code.gs）と index.html（名前は index）を貼り、appsscript.json を置き換える
2. エディタで setupTabicho を1回実行（権限承認。保存用スプレッドシートが作られる）
3. デプロイ → 新しいデプロイ → ウェブアプリ（実行ユーザー：自分／アクセス：自分のみ）
4. スクリプトプロパティ：
　SPOTCHO_URL／SPOTCHO_PIN（スポット帳の SECRET_PIN）／PLACES_API_KEY（スポット帳と同じキー）／
　KAKEIBO_URL／KAKEIBO_PIN（家計簿の SECRET_PIN）／SHIFT_MASTER_SS_ID（家計簿GASの SALARY_SS_ID と同じ）
　任意：WORK_CALENDAR_ID／WORK_OFF_REGEX／SHIFT_AKE_IS_OFF／WORK_EMPTY_IS_OFF／TRAVEL_CALENDAR_ID
5. 家計簿：アプリを index-v7.1.html に差し替え。GAS は gas-v7.1.txt に置き換えてもよい（処理は同じなので再デプロイ不要）
6. スポット帳：変更なし。「絶対行きたい」を使う場合は tags タブにジャンルとして1行足す
7. 旅帳の設定（歯車）で 自分の名前・自宅・支払方法を確認し、「接続テスト」で スポット帳・家計簿・カレンダー・経路 が通るか確認
