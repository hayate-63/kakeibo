B. しおり＆精算の画像書き出し（17_export.js）
━━━━━━━━━━━━━━━━━━━━━━━━
作り：描く中身（行・文字）を作る関数と、Canvas に描く関数を分けた。中身の関数は単体テストで確かめている。
見た目は VTHEME（トラベルマガジン風）、書き出しは exportCanvases（共有シート → 使えない環境は画像一覧）

B-1 しおり画像
・入口：しおりタブ（工程）の上、モード切り替えの右に［📤 画像で書き出し］
・オプション（モーダル）：
　- 出力するもの：表紙／各日（予定がある日だけ既定 ON）／未配置の「行きたい場所」（既定 OFF。リストモードの旅は ON）
　- 🔒 金額・予約番号・メモを隠す（既定 OFF）。ON の時は 料金目安・予約番号・工程のメモを描かない
　- サイズ：9:16（1080×1920）／縦長（幅1080・高さは内容に合わせる）
　- 選ぶたびにプレビュー（縮小）を作り直し、ボタンに枚数（［📤 N枚を書き出す］）
・9:16 で予定が多い日：まず文字を小さく（最小 0.82 倍）、それでも入らなければ複数枚に分ける（DAY 1 (1/2) のように表示）
・縦長：1日1枚。ただし 8000px を超える極端に長い日だけ分ける（iPhone の Canvas の上限 約1,670万画素 に近づかないため。メモに無い追加）
・描く内容：
　- 表紙：TRAVEL ITINERARY、英語タイトル（英語にできていない時は旅のタイトルを大きく）、旅のタイトル、日程（fmtDateFull）、
　　泊数／日数、メンバー、エリア、乗り物、各日の要約（DAY 1：A → B → C。5件以上は「ほか◯件」）
　- 日別：DAY N・日付（曜日つき）・天気（キャッシュにある時）、番号入りの丸、開始〜終了、名前、固定枠🔒、滞在、
　　工程の間の移動（乗り物・分・距離）、料金目安・予約番号・メモ（2行まで。プライバシー OFF の時だけ）、フッターに旅のタイトルと「旅帳」
　- 未配置リスト：⭐絶対／☆行けたら・名前・エリア・営業時間の要約（9:16 は 9件ごとに1枚）

B-2 精算カード
・入口：お金タブ →「🤝 精算」の一番上に［🧾 精算カードを書き出し］
・オプション：全員まとめ（1枚・既定）／送金ごと（1件1枚）、支出の内訳を載せる（既定 ON。送金ごとの時に効く）
・幅 1080 固定、高さは行数に合わせて伸ばす（最小 1350）。長すぎる時（本文 2600px 超）は複数枚に分ける
・見た目：生成りの紙（VTHEME.paper）、上下のミシン目、点線の区切り、金額は等幅フォントで右揃え
・全員まとめ：SETTLEMENT RECEIPT・旅のタイトル・日程・精算通貨・総額・1人あたり目安、送金リスト（枠で囲んで金額を大きく）、
　メンバー別（払った／負担／差額）、注記「割り勘の端数は支払者が負担しています」
・送金ごと：「〇〇さん → △△さん」と金額を大きく、内訳 ON の時は 負担した支出（日付・内容・1人分）→ 負担合計 → 立て替え分の相殺（マイナス）→ 差し引き。
　1人が複数の人に分けて送る場合はその注記
・数字は computeTransfers(trip) の結果だけを使う（画面の精算と同じ。テストで送金額の一致を確認）
・精算が0件の旅：全員まとめは「✅ 精算の必要はありません」とメンバー別の1枚を作れる。送金ごとは「精算はありません」と表示し、
　書き出しボタンは押せない（作るカードが無いため）

C-1 寄り道レーダー
・入口：ドライブタブの一番上に［🧭 寄り道を探す］（車の旅・電車の旅どちらでも出る）
・押した時に現在地を取り直す（5分以内に取れていればそれを使う）。取れなければ「現在地が分かりません」と出して終わる（推測の出発地は使わない）
・候補：スポット帳の「行きたい」で訪問記録の無いもの ＋ この旅の未配置リスト（同じスポットは1つ。今日の工程に入っているものは除く）
　※ むぎ提案は「スポット帳の行きたい未訪問」。この旅のリストの方が目的に合うので足した（変更点①）
・判定（この順）：
　1. 座標があるもの
　2. 今営業中。営業時間が分からないものは残して後ろに並べる（開店前・閉店後・定休日は出さない）
　3. 移動（現在地→スポット）＋滞在（スポット帳の滞在目安、無ければ60分）＋移動（スポット→次の予定の場所）が、次の予定の開始までに収まる。
　　次の予定＝今より後に始まるまだ行っていない工程。固定枠はその時刻、通常の工程は daySchedule の算出時刻。
　　次の予定の場所に座標が無い時は、戻りの移動を 0 として計算（変更点②：むぎ提案に無い場合の扱い）
　　次の予定が無い日は 24:00 まで（「今日中なら自由」）
　追加の条件：営業中でも「着いた時に閉店まで30分（滞在がそれより短ければ滞在分）無い」ものは出さない（変更点③：着いたら閉まっている、を防ぐ）
　4. 所要はまず estimateMinutes（概算）で絞り、距離の近い上位6件だけ routeFor（経路キャッシュ）で実際の所要に置き換える。
　　実際の所要が届いたら一覧を描き直す（戻りの移動は概算のまま）
・表示：営業中を距離の近い順 → 営業時間不明を距離の近い順。名前・距離・移動（概算なら「概算」）・滞在・次の場所までの移動・
　営業状態（閉店までの分）・「余裕◯分（間に合う）」または「今日中なら自由」
・［＋ 工程に差し込む］：今日の工程の、今の時刻の位置（次の予定の直前）に入れる。開始は「今＋移動」を5分単位で切り上げた時刻で、
　時刻を手で決めた扱い（startManual）にする。固定枠は動かさない。差し込み後に移動時間を経路で計算し直す
・［🧭 このままナビ開始］：既存と同じ Google マップの経路案内リンク

C-2 仮しおりの自動生成（定休日パズル）
・入口：しおりタブの「未定（未配置）」／「行きたい場所」の見出しに［🪄 自動で案］（未配置があり、日程がある時だけ）
・対象：未配置の「行きたい場所」だけ（既に工程に入っているものの並べ替えはしない。むぎ提案どおり）
・ルール：
　1. 定休日（dayAvailability が closed）の日には入れない。営業時間不明の日は入れてよいが、プレビューに「営業時間未確認」
　2. 固定枠🔒と時刻を決めた工程は動かさない。その前後の空きに入れる
　3. 並べ方：移動が一番増えない位置に1つずつ入れ（最安挿入）、新しく入れたものが続く区間の中で 2-opt をかける。
　　距離は haversineKm、所要は estimateMinutes。外部 API は呼ばない
　　※ むぎ提案は「最近傍法＋2-opt」。既存の工程（固定枠を含む）の間に差し込む必要があるため、近い順に1つずつ足す最近傍法の代わりに、
　　　「既存の並びを変えずに、どこに入れると移動が一番増えないか」で決める最安挿入法にした（変更点④）。2-opt はそのまま
　4. 絶対行きたい → 行ける日が少ないもの（定休日が多いもの）→ 行けたら の順に入れる。入りきらないものは未配置のまま残す
　5. 1日は 設定の「1日の開始時刻」〜21:00（設定に終了時刻が無いため 21:00 固定）。
　　入れた結果、固定枠が「間に合いません」になる配置はしない。営業時間内に収まらない配置もしない（開店前に着く時は開店まで待つ）
　6. 各日の出発点：前の日の最後の場所（宿の固定枠など）、1日目は旅の出発地
・プレビュー：配置した件数・総移動時間・定休日を避けた件数・営業時間未確認の件数、日ごとの並び（時刻・移動・🆕・開店待ち）、
　未配置のまま残すもの（理由：座標がない／旅の日程がすべて定休日／時間内に入りきらない）
・［この案をしおりに反映］で初めて書き込む。プレビューは旅のコピーで作るので、［キャンセル］では何も変わらない
・反映の内容：新しく入れたものに日付と並び順。開店を待つものだけ開始時刻を入れる。前後の移動時間は概算を入れ、反映の後に経路で計算し直す。
　既存の工程は並び順の番号を振り直すだけ（順番・固定枠の時刻は変えない）。リストモードの旅はしおりモードに切り替える

■ むぎ提案から変えた点（まとめ）
①C-1 の候補に、この旅の未配置リストも入れた ②次の予定の場所に座標が無い時は戻りの移動を0 ③着いたら閉店、を出さない条件を追加
④C-2 は最近傍法の代わりに最安挿入法（既存の工程の間に入れるため）＋2-opt。いずれもデータ構造とは矛盾なし
