1. 項目ごとの対応
==================================================
【項目1 保存中のローディング表示】
　・全画面の半透明オーバーレイ（rgba(0,0,0,.35)）＋中央に回るスピナー＋ラベル。
　　z-index 4000（ロック画面 5000 より下、通常画面・モーダル 1000 より上）
　・api() で一括して付ける（ボタンごとの実装なし）。api() を通る全アクションが対象：
　　同期・スポット追加/編集/削除・訪問記録の保存/編集/削除・写真アップロード・CSV取り込み・
　　設定保存・キューのチェック保存・検索・ジャンル判定・座標補完 など
　・ラベル：保存系「保存中…」／同期「同期中…」／検索「検索中…」／写真「写真を保存中…」／
　　ジャンル「ジャンル判定中…」／座標「座標を補完中…（n／m）」
　・カウンタ方式（通信が重なっても途中で消えない）。成功・失敗とも finally で減らす
　・表示中は下の画面を押せない（オーバーレイが全面でタップを受ける）
　・最低300ms表示（実測 299〜300ms）。右上バッジは従来どおり

【項目2 保存・同期の結果表示】
　・成功：画面下中央の緑トースト「✓ 〇〇」、2.5秒で消える。文言：
　　スポットを保存しました／スポットを更新しました／スポットを削除しました／
　　訪問記録を保存しました（写真付きも同じ）／訪問記録を削除しました／◯件を取り込みました／
　　設定を保存しました／同期しました（◯件）／◯件のスポットに◯個のタグを追加しました
　　検索（searchPlace／resolveUrl）・ジャンル判定・写真単体には出さない
　・失敗：画面下の赤バナー。×で閉じるまで残る。①何が（「スポットの保存に失敗しました」等）
　　②理由（AUTH＝「パスワードが一致しません。設定タブで確認してください」、
　　NETWORK＝「通信できませんでした。電波の良い場所で再試行してください」、
　　それ以外は GAS の message をそのまま。HAS_VISITS・DUPLICATE も GAS の文言）③次の行動
　　（同期は［再試行］、AUTH は［パスワードを合わせる］、保存系は「入力内容はそのまま残っています。
　　直してもう一度保存してください」。フォームは閉じない）
　・順序：スピナーが消えてから結果を表示（検証で確認）
　・同期が成功したらバナーは自動で消える
　・バナー表示中は画面の下に余白を足し、保存ボタン等をバナーより上までスクロールできる
　　（検証中に「バナーが保存ボタンに被って押せない」ことが分かったため追加）
　・従来の個別の toast／alert（保存しました・削除しました・GAS エラーの alert）は撤去し、一本化

【項目3 名称検索＋ジャンルフィルター】
　・対象：県ページの一覧、思い出ノート
　・店名の部分一致（全角半角・大文字小文字を区別しない）。入力はその画面を開いている間保持
　・ジャンル：その一覧に含まれるジャンルだけをチップで表示（グループ順・件数付き）。複数選択は OR
　・既存の「訪問済だけ／未訪問だけ」と AND。件数表示「152件中 10件を表示」
　・思い出ノート：訪問したスポットのタグで判定。サマリーは全体のまま、タイムライン上部に
　　「◯件中◯件を表示」。入力中にフォーカスが外れないよう、一覧部分だけを描き直す

【項目4 ジャンル全追加＋自動判定】
　・tags タブを8列に：タグ名／絵文字／並び順／種別／代表優先順／判定キーワード／Places種別／グループ
　・確定ジャンル114種（genre-master-v30 の全件）＋既存の「定期」「コーティング周辺」（グループ＝その他）
　・既存DBの移行（migrateTagsV3_）：GAS の最初のアクセスで1回だけ。列を足し、新ジャンルを追加、
　　既存ジャンルは絵文字・種別をそのまま、並び順・代表優先順・判定辞書・グループを確定版にする
　・判定は GAS の classifyGenres に一元化（辞書は tags タブ。シート編集だけで足せる）。
　　判定キーワードの書き方（シートの判定キーワード欄、「|」区切り）：
　　　語        … 店名に含めば付ける（英字の大小・全角半角は区別しない）
　　　語$       … 店名の末尾がその語なら付ける（寺$・城$・滝$）
　　　語@項目   … その項目のスポットで、かつ「!語」を含まない時だけ付ける（麺@グルメ・タワー@観光地）
　　　-語       … 店名のその部分は判定に使わない（中華 の -中華そば、バー の -バーガー）
　　　!語       … 「語@項目」の弱いキーワードを止める（ラーメン の !うどん・!そば）
　　Places種別が一致した場合も付ける。どちらも「追加」方向のみ
　・駐車場と判定された場所は実用グループ以外のタグを付けない
　　（例：「あわじ島アイスクリーム専用第二駐車場」→ 駐車場だけ。アイスにはしない）
　・店名が住所そのもの（〒〜）の場合は店名キーワードで判定しない（地名の誤判定防止）
　・新規登録（店名検索・URL）：候補を選んだ時点で GAS が判定 → 確認カードに
　　「自動判定：ジャンル＝…」と表示し、グループ別のチップで付け外しできる。
　　確認カードで判定済みの場合は addSpot で二重に足さない（外したタグを勝手に戻さない）
　・手入力の新規：判定前なので addSpot 実行時に GAS が判定し、本人のタグと合体（重複除く）
　・食べ物系グループ（麺・和食・肉・各国）のジャンルが付いたら項目「グルメ」も付ける
　・設定タブ［ジャンル再判定］→ reclassifyAll：全スポットの店名＋項目で判定し、足りないタグだけ追加
　　（削除なし）。代表タグは自動で決まっていたもの（空 or 旧タグからの自動値）だけ付け直し、
　　手で選んだ代表タグは残す。終了時「◯件のスポットに◯個のタグを追加しました」＋内訳
　・ジャンルタブ・編集画面・地図のタグ選択をグループ見出し付きに（麺／和食／肉／各国／カフェ・甘味／
　　酒／癒し／観光／アウトドア／宿／買い物／実用／属性／その他）

【項目5 地図マーカーの反映条件の緩和】
　・座標の探し方（GAS resolveCoords_）：マップURLの座標（短縮URLは展開。無料）→
　　place_id の Places 詳細 → 住所の Nominatim（無料・1秒間隔）→ 店名＋都道府県＋市区町村の Places 検索
　・設定タブと未処理キューに［座標を自動補完］（fillCoords）。20件ずつ・約4分で区切り、
　　アプリが繰り返し呼ぶ。見つからなかったものは同じ実行の中で再試行しない。結果に内訳
　・新規登録で座標が無い場合：確認カードに「座標が取れなかったため、このままでは地図に表示されません」
　　＋［店名で検索して選び直す］。保存時に自動補完を試し、見つからなければ
　　「地図には表示されません。このまま保存しますか？」と確認（黙って保存しない）
　・地図上部に「全◯件中 ◯件を表示中（座標なし◯件は地図に出ません）」＋［絞り込みリセット］
　・クラスター表示は維持

【項目6 上部UIの被り・押しにくさ】
　・apple-mobile-web-app-status-bar-style を black（不透明）に。theme-color は #1e293b のまま
　・戻るボタン：padding 10px 14px・14px 文字・最小高さ44px・最小幅64px。view-header は最小60px＋セーフエリア
　・地図フィルターの sticky 位置をヘッダーの実高さ（JS で測って CSS 変数 --header-h）に合わせる。
　　画面回転・リサイズ時も測り直す
　・ヘッダー類の背景は完全に不透明（検証で alpha=1 を確認）

2. 要確認（判断に迷ったため仮決めした点）
==================================================
D-1 既存ジャンルの絵文字：確定版の一覧には うなぎ🍥／すき焼き🍲／スキー場🎿／美容💈／
　　車 写真撮影場所🚗 と書かれているが、同じ箇所に「既存の絵文字のまま」「既存ジャンルの絵文字は
　　変更しない」とあるため、今の絵文字（📌／🥓／🏂／💉／📸）を残した。一覧の絵文字にしたい場合は
　　tags タブの絵文字欄を書き換えるだけで反映される。
D-2 Places種別名の実在確認：検証環境から Google の公式ドキュメント（Place Types Table A）に
　　接続できず、確認できていない。種別は「一致したら追加」の補助で、存在しない種別名は何も起こさない
　　（誤判定にはならない）ため、確定版の種別名＋近い候補をそのまま入れた。主軸は店名キーワード。
　　確実に古くからあるもの：ramen_restaurant sushi_restaurant chinese_restaurant italian_restaurant
　　pizza_restaurant hamburger_restaurant indian_restaurant korean_restaurant thai_restaurant
　　vietnamese_restaurant french_restaurant seafood_restaurant steak_house buffet_restaurant bar
　　wine_bar bakery ice_cream_shop donut_shop museum art_gallery aquarium zoo amusement_park park
　　campground ski_resort golf_course hiking_area gas_station parking hospital drugstore pharmacy
　　supermarket book_store gift_shop car_wash electric_vehicle_charging_station 等。
　　それ以外（udon_noodle_restaurant・yakiniku_restaurant・shinto_shrine・onsen 等）は要確認。
　　確認後、tags タブの Places種別欄を直すだけでよい。
D-3 判定辞書を確定版から調整した点（誤判定の防止。実データ529件で確認して直した）：
　　・パン → 「パン屋|ベーカリー|ブーランジェリー|ベッカライ」（「パン」単独はジャパン・パンケーキで誤爆）
　　・インドカレー：「ナン」を外し「インド|ネパール」に（「ナン」はナンバ等で誤爆）
　　・うなぎ：「ひつまぶし」を外した（「鴨ひつまぶし」で誤爆）
　　・ラーメン：「麺」は 麺@グルメ（グルメの時だけ）で、うどん・そば・パスタ・冷麺・製麺 を含めば使わない
　　　（「がいな製麺所」はうどん店）
　　・そば・中華は「中華そば」「焼きそば」等を除外、台湾料理は「台湾ラーメン」「台湾ドーナツ」等を除外
　　・バーは「バーガー」「barn」等を除外（「COFFEE BARN」で誤爆）
　　・展望台・タワー：「タワー」は観光地の時だけ（「〜ホテルズ大阪ザ・タワー」で誤爆）
　　・寺・城・滝は末尾一致（寺$ 等）。桜・紅葉は観光地の時だけ。フォーは弱いキーワード
　　・病院：美容クリニック・美容外科クリニックは除外。公園：「公園前」「公園通」は除外
　　・和菓子：「洋菓子」は除外（「洋菓子舗ルタオ」）
　　・美容：確定版の「美容室|美容院|ヘアサロン|理容」に、v1.0 からの「美容外科|美容皮膚科|美容クリニック」を残した
　　　（既存の美容タグ💉は美容医療の意味で使われていたため）
　　・追加した語：ぎょうざ／焼鳥／もんじゃ（お好み焼き）／串カツ／饅頭／ENEOS・出光等（ガソスタ）／
　　　パーキング（駐車場）／医院（病院）／記念館・資料館（博物館）など
D-4 グループの割り当て：一覧の行に従い、居酒屋＝和食、ビュッフェ＝各国、ドライブ・SA/PA＝アウトドア、
　　フォトスポット・Friend＝属性、車 写真撮影場所＝観光、定期・コーティング周辺＝その他 とした。
D-5 移行時、既存ジャンルの「並び順」「代表優先順」は確定版で上書きする（絵文字・種別は保持）。
　　確定版で中華がすき焼きの後、美容がキャンプ場の前に変わったため、既存スポットの代表タグは
　　自動では付け直さない（ジャンル再判定でタグが増えたスポットだけ再計算）。
D-6 reclassifyAll の書き込み：件数が多いため tags／rep_tag／updated_at の3列をそれぞれ1回でまとめて
　　書く（変わった行の値だけが変わる）。行ごとの書き込みだと数百回の書き込みで時間切れの恐れがあるため。
D-7 店名検索による座標補完は、同名の別店舗に当たる可能性がある（都道府県・市区町村を添えて検索）。
　　補完したスポットは coord_source＝Places（URL／Nominatim）で見分けられる。place_id は付けない。
D-8 起動時の自動同期にもスピナーと「同期しました（◯件）」が出る（L7 の仕様どおり、毎回）。
D-9 キューのチェック保存は「設定を保存しました」ではなく「チェックを保存しました」と出す。
D-10 地図フィルターの sticky 位置は、地図フィルターが乗っている上部ヘッダー（header）の実高さに合わせた
　　（地図タブはオーバーレイ画面ではないため、view-header ではなく header が基準）。
D-11 実データでのジャンル再判定の結果（529件）：93件のスポットに100個のタグを追加
　　（うどん6・温泉6・ハンバーガー5・定食・食堂5・餃子5・たこ焼き5・パスタ4・喫茶店4・滝4・公園3 など）。
　　誤判定は上記 D-3 の調整後、目視で見当たらなかった。

4. デプロイ手順書（v2.0 → v3.0、本人の作業）

【GAS（同じプロジェクト・同じURLのまま更新）】
　1. GAS エディタの中身を gas-v3.0.txt（または .gs）で丸ごと置き換える
　2. 冒頭の SECRET_PIN を今のパスワードに書き直して保存（置き換えで '0000' に戻るため）
　3. 関数 setup を選んで ▶実行（tags タブに列と新ジャンルが追加される。権限の追加承認は無し）
　4. デプロイ → デプロイを管理 → 鉛筆 → バージョン「新バージョン」→ デプロイ
　　※「新しいデプロイ」にすると URL が変わる
【HTML】
　5. Netlify の index を index-v3.0.html の中身に差し替える
【初回だけ】
　6. アプリの設定タブ →［🏷️ ジャンル再判定］→ 「◯件のスポットに◯個のタグを追加しました」
　7. 座標の無いスポットがあれば［📍 座標を自動補完］（設定タブの説明に今の件数が出る）
【確認】
　8. 何か1件を編集して保存 → 中央にスピナー → 「✓ スポットを更新しました」
　9. ジャンルタブがグループ見出しで並ぶ、県ページに「店名で絞り込み」とジャンルのチップが出る
