1. 対応内容
==================================================
【第1部 スクショから追加（OCR）】
　・追加タブの「📷 スクショから追加」を独立したカードにし、［画像を選ぶ］を有効化。「v1.1で対応」は削除
　・画像を選ぶ → アプリで長辺1600px・JPEG に圧縮（訪問写真と同じ compressImage）→ GAS ocrImage
　・GAS ocrImage：画像を Google ドキュメントとして作成（Drive API v3、ocrLanguage＝ja）→
　　DocumentApp で本文テキストを取得 → 一時ファイルは finally で必ずゴミ箱へ（成功・失敗とも）。
　　一時ファイルは「スポット帳 写真」フォルダ内に作る（万一ゴミ箱に移せなくてもマイドライブ直下を汚さない）。
　　Drive API v2 のままのプロジェクトでも動くよう Files.insert（ocr:true）にも対応
　・Drive API を追加していない場合は NO_DRIVE_API で「サービス → Drive API を追加」と案内
　・店名候補の抽出：上から順に最大5行。除くもの＝空行・2文字未満・40文字超・時刻／電池／評価／距離など
　　数字と記号だけの行・URL・郵便番号から始まる住所行・地図アプリの操作ボタンの文字
　　（経路／保存／共有／電話／クチコミ／営業中 など）
　・候補をタップ → その文字が入力欄に入って検索 → 既存の検索結果UI → 選ぶ → 確認カード
　　（項目・県・ジャンルの自動判定つき。v3.0 と同じ流れ）→ 保存
　・入力欄で店名を手で直して検索し直せる。読み取った全文は折りたたみで見られる
　・文字が取れない／店名らしい行が無い：「文字を読み取れませんでした」＋手入力の検索欄（カーソルが入る）
　・通信中は v3.0 のスピナー（「文字を読み取り中…」）。失敗時は赤バナー「文字の読み取りに失敗しました」
　　＋カード内でも手入力へ誘導。成功時のトーストは出さない（保存ではないため）
【第2部 クリップボードから貼り付け】
　・リンク入力欄の横に［📋 貼り付け］。クリップボードの文字から URL 部分だけを取り出して入れ、
　　そのまま既存の「読込」（resolveUrl）へ進む。URL が無ければ文字だけ入れる
　・読み取れない（空・許可されない）時は「入力欄を長押しして『ペースト』してください」と案内

【実装しないもの（引き継ぎメモどおり）】
　共有シート（ショートカット）からの追加、共有URLの自動振り分け、写真の位置情報（EXIF GPS）からの追加

2. 要確認
==================================================
E-1 実際の OCR は実 GAS（Google ドライブ）でしか動かないため未検証。テストは OCR 結果をモックで返して
　　流れを検証した。精度（特に縦書き・装飾文字・リール動画の字幕）は実機で確認が必要。
E-2 店名候補に「ラーメン」のような業種の行が混ざることがある（店名の下に業種が出る画面のため）。
　　上から順なので店名が先頭に来る想定。違う時は候補を選び直すか手で直す。
E-3 GAS の権限：v3.1 で DocumentApp（ドキュメント）を使うため、更新後に setup を実行すると
　　「Google ドキュメントの表示・編集」の承認が追加で出る。
E-4 iPhone の Safari では、［貼り付け］を押した時に「ペースト」の確認が出ることがある（iOS の仕様）。
E-5 検証スクリプトのパスワード設定の確認（P2a）が1回だけ不安定だったため、メッセージの更新を待つ形に
　　直した（アプリ側の問題ではない。単体で25回試して再現せず）。

　 作成・ocrLanguage＝ja）→ 候補「テスト中華そば 四日市店／ラーメン／喫茶me」（時刻・電池・評価・住所・URL・

　 Drive API 未追加の GAS は NO_DRIVE_API で案内。PIN が違えば ocrImage も AUTH で拒否

S7 ［貼り付け］：「この店よかった https://www.google.com/maps/place/…」から URL だけが入り、そのまま候補が出る。
　 クリップボードが空なら長押しでの貼り付けを案内
