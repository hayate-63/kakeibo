1. 仕様との対応
==================================================
【§1 構成・認証・通信】
　・単一HTML＋GAS＋スプレッドシート。地図ライブラリのみCDN（unpkg：Leaflet 1.9.4、
　　Leaflet.markercluster 1.5.3）
　・通信：POST、Content-Type text/plain;charset=utf-8、本文 JSON {action, pin, ...}。
　　応答 {status:"ok", ...}／{status:"error", code, message}（家計簿の status:"ok" 形式に合わせた）
　・PIN：HTML側ロック画面（PINのSHA-256ハッシュを端末に保存）＋ 全リクエストで pin を送り、
　　GAS 側で SECRET_PIN と照合（不一致は code:"AUTH"）。doGet はデータを返さない

【§2 DB】
　・spots：列は spots-import-v10.csv のヘッダーと完全一致（21列、検証で一致確認）。
　　シート全体を書式なしテキスト（@）にして、日付・数値・place_id の自動変換を防止
　・tags：タグ名／絵文字／並び順／種別／代表優先順（★5列目は追加。要確認 A-2）。
　　初期値は §5 の絵文字対応表（ジャンル18＋項目6）＋地域タグ7（要確認 A-3）
　・config：key／value。places_api_key（初期値空）、地図タイルURL・出典4件、queue_checks
　・初期データ：設定タブ → CSVインポートで spots-import-v10.csv を選ぶ → importSpots。
　　529件そのまま入る（§9 V1）

【§3 GAS アクション】
　getAll ……… spots全件＋tags＋config（places_api_key の値は返さず、設定済みフラグのみ）
　addSpot ……… id＝最大値＋1（SP0001形式）、place_id 重複は code:"DUPLICATE"＋existingId で返す。
　　　　　　　　google_saved 既定＝未、created_at／updated_at＝GAS側の当日
　updateSpot …… id で対象行を探し、その1行だけ setValues。updated_at＝当日、created_at は保持。
　　　　　　　　place_id を他スポットと重複する値に変えた場合も DUPLICATE
　deleteSpot …… 対象行を deleteRow
　importSpots … 既存行と place_id／マップURL（URL中の 0x…:0x… 地物ID、無ければURL文字列）で
　　　　　　　　重複判定し、新規分だけを末尾にまとめて追記。結果 {added, skipped, total, skippedDetail}
　searchPlace … Places API (New)。query → Text Search（候補一覧）、placeId → Details（住所構成要素・
　　　　　　　　マップURL付き）。キー未設定は code:"NO_API_KEY"
　（追加）resolveUrl … 入口1用。短縮URL展開→URL解析→（キーあり）Details／Text Search で特定、
　　　　　　　　（キーなし）URL座標＋Nominatim 逆ジオで候補作成（要確認 A-9）
　（追加）setConfig … config の1キーを書き換え（APIキー・タイルURL・キューのチェック状態）
　書き込みはすべて LockService で排他。全件再書き込みは無し。

【§4 画面】
　タブ1 ホーム：キーワード検索（店名・住所・メモ＋県・市を横断、空白区切りAND）／
　　47都道府県グリッド（地方別、0件もバッジ0で表示）／近くのスポット（現在地から近い順10件＋
　　「もっと見る」）／最近見た（端末に20件保持）／最近追加した
　　県ページ：すべて＋カフェ／宿／グルメ／観光地を常時表示、服は愛知・大阪・京都・東京で常時表示。
　　空は「◯◯ のカフェはまだ0件」。「この県を地図で見る」
　タブ2 地図：§6 参照
　タブ3 追加：アプリ内検索（入口3）／リンク（入口1）／手入力／スクショ（v1.1の置き場所のみ、
　　ボタン無効）／Google未保存キュー／未処理キュー
　タブ4 ジャンル：ジャンルタグ・地域タグ・項目の一覧（件数付き）→ 一覧＋「地図で見る」
　タブ5 設定：GAS URL／Places APIキー／PIN変更／CSVエクスポート・インポート／地図タイル
　一覧の並び替え：距離順／名前順／登録日順／評価順（全一覧共通）
　詳細：店名・項目チップ・タグ・住所・距離・評価・メモ＋［ナビ開始］［Googleマップで開く］［編集］
　　［地図で表示］、代表タグ（マーカー絵文字）の変更セレクト
　ナビ開始：https://www.google.com/maps/dir/?api=1&destination=緯度,経度(&destination_place_id=)

【§5 分類と絵文字】
　・項目・タグは複数選択（排他なし）
　・自動判定（新規追加時）：Places 種別→項目（cafe/bakery等→カフェ、lodging系→宿、
　　restaurant/food/〜_restaurant→グルメ、tourist_attraction/museum/park/神社寺等→観光地、
　　clothing_store→服）、種別→タグ（ramen_restaurant→ラーメン、yakiniku→焼肉、sushi→寿司、
　　chinese→中華、parking→駐車場、gas_station→ガソスタ ほか）＋店名キーワード辞書（設計メモ §8）。
　　食べ物系タグが付いたらグルメも付与。都道府県は addressComponents → 無ければ住所文字列から。
　　判定結果は確認カードに表示し、保存前に全項目修正可
　・代表タグ自動決定：tags タブの「代表優先順」の昇順（初期値＝うなぎ＞ラーメン＞…＞Friend）。
　　移行データ529件の rep_tag はこの規則と全件一致することを確認済み
　・マーカー絵文字：代表タグの絵文字 → 無ければ最初の項目の絵文字 → 📍

【§6 地図】
　・Leaflet。標準＝OSM、航空写真＝Esri World Imagery（右上🛰️で切替）。出典表示あり。
　　タイルURL・出典は config で差し替え可（設定タブからも編集可）
　・divIcon（白丸＋絵文字）、markercluster で密集地は件数バッジ
　・マーカーtap → 下部カード（大絵文字・店名・項目/タグチップ・住所・距離・評価・メモ、
　　［ナビ開始］［Googleマップ］［詳細・編集］）
　・上部：項目チップ（すべて／カフェ／宿／グルメ／観光地／服／その他、複数ON可）＋
　　都道府県・タグ・状態のセレクト。すべて AND で連動
　・地図移動（moveend）で「この範囲のスポット（N件）」を下に表示（中心から近い順、最大50件表示）
　・現在地ボタン。写真表示なし

【§7 二層運用】
　・新規追加は google_saved＝未 → Google未保存キューに入る（対象外ボタンあり）
　・保存先リスト名＝「都道府県×項目」（その他を除く）＋ジャンルタグ名。複数なら複数行。
　　リスト名の表記は既存 source_lists の表記を優先（例：「大阪　グルメ」は全角スペースのまま、
　　「京都カフェ」は空白なし）。無ければ「三重 グルメ」形式
　・各行：チェック欄＋タップで Googleマップを開く。全行チェックで「済にしますか？」→ 済
　・チェック状態は config の queue_checks に保存（端末をまたいで共有）
　・移行済み529件は 済 のためキューに入らない

【§8 入れていないもの】
　スクショ保存（置き場所のみ）、写真表示、ログイン・複数ユーザー

2. 要確認（判断に迷ったため仮決めした点）
==================================================
A-1 PIN方式：リポジトリにある家計簿（into.html）には PIN の実装が見当たらず、家計簿の GAS も
　　手元に無いため、「HTMLでロック＋GASで SECRET_PIN 照合」を上記のとおり新規に作った。
　　家計簿の実際の方式（PINの保存場所、自動ロックの有無など）と違えば合わせ直す。
　　PIN変更はアプリ側のみで、GAS の SECRET_PIN は手で書き換えて再デプロイが必要。
A-2 tags タブに5列目「代表優先順」を追加：引き継ぎメモは4列だが、優先順リストに無い
　　「定期」「コーティング周辺」を自動代表から外す必要があり、並び順（表示順）と優先順が
　　別物のため列を分けた。空欄＝自動代表の対象外。
A-3 地域タグ（淡路島・飛騨高山・上高地・函館・札幌・小樽・登別）を tags マスタに
　　種別「地域」・絵文字空で追加した（ジャンルタブ・地図の絞り込みに使うため）。
A-4 CSV の prefecture に47都道府県以外が5件ある：
　　SP0045（空欄・シンガポール）、SP0047「Washington県」、SP0081「フロリダ州県」、
　　SP0434「Taichung City県」、SP0454「California県」。
　　「内容を変更しない」指示に従い値はそのまま。ホームの47県グリッドの下に
　　「海外・都道府県不明」枠を（該当がある時だけ）表示している。データを直すかは本人判断。
A-5 §9 V4 の例「沖縄県」は実データでは1件ある（SP0408、項目＝その他）。
　　0件の県としては青森県で検証し、沖縄県・愛知県も併せて検証した。
A-6 CSV 内で place_id が重複している組が5組ある
　　（ChIJHXk9tgBrBGARyGtihXgPHpQ／ChIJfRQpcrdqBGARTsmfs21P_Cs／ChIJC8XxEJAOHWARBzhcrx9Cbpo／
　　 ChIJrQS24NZFHWARD_fCBRWQw8U／ChIJN8pnSBDnAGARWptJEKh5PSg）。
　　初期投入は「件数・内容は変更しない」を優先し、CSV 内の重複は除外せず529件そのまま入れる
　　（既存行との重複だけ除外）。Takeout 再取込では同じ取込内の重複も1件にまとめる。
　　統合するかは本人判断。
A-7 県ページに「すべて」タブを追加し、「その他」タブは件数がある県だけ表示。
　　服タブは4県のほか、服が1件以上ある県でも表示（現データでは4県以外に服は無い）。
A-8 未処理キューの定義：座標または都道府県が空のスポット＋メモに「要確認」を含むスポット
　　（移行時の「要確認: 項目は種別から決められず『その他』」など。現データで86件）。
　　タップで編集画面。ショートカット経由のリンク共有→キュー投入（設計メモ §5 入口1）は、
　　v1.0 ではアプリにURLを貼る方式で実装し、共有シート連携は入れていない。
A-9 入口1（リンク）：Places キー未設定でも、URL に座標があれば URL 座標＋Nominatim
　　（無料）で住所・都道府県を補って候補にする。この場合 place_id は空、coord_source＝URL。
A-10 Places API の費用：Text Search の取得項目に location・types を含めているため、
　　Text Search は Pro 区分の課金になる。候補選択後に Details を1回呼ぶ。
　　Google Cloud 側でクォータと請求アラートの設定を推奨（設計メモ §8）。
A-11 Google未保存キューの保存先に「地域タグのリスト」（淡路島　グルメ 等）は含めていない
　　（引き継ぎメモ §7 の定義どおり）。必要なら追加する。
A-12 未実装：Service Worker（オフライン起動）。前回取得データは端末にキャッシュして即表示する。
　　ホーム画面アイコン（apple-touch-icon）は起動時に📍で生成。設計メモ §7 の「よく行く県の
　　ピン留め」は引き継ぎメモに無いため v1.0 では入れていない。
A-13 GAS は単体プロジェクトで動くよう、初回 setup で「スポット帳DB」スプレッドシートを
　　自動作成し ID をスクリプトプロパティに保存する（スプレッドシートから開いた
　　コンテナバインドの場合はそのシートを使う）。

4. デプロイ手順書（本人の作業）
==================================================
【GAS】
　1. https://script.google.com で「新しいプロジェクト」→ 名前「スポット帳」
　2. gas-v1.0.gs の中身を丸ごと貼る（既存の function myFunction は消す）
　3. 冒頭「設定」にある SECRET_PIN = '0000' を、本人の現在のPIN（家計簿と同じ）に書き換えて保存
　4. 関数一覧から setup を選んで ▶実行 → 権限を承認
　　（スプレッドシート「スポット帳DB」が作られ、spots／tags／config タブができる。
　　 実行ログにURLが出る）
　5. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
　　 実行ユーザー：自分　アクセスできるユーザー：全員 → デプロイ → URL をコピー
　　 ※家計簿とは別URL。コードを直したら「デプロイを管理 → 編集 → 新バージョン」で更新
【HTML】
　6. Netlify に index-v1.0.html を配置（index.html にリネームして置くとトップURLで開ける）
　7. iPhone の Safari で開く → 共有 →「ホーム画面に追加」
【初期設定】
　8. 初回起動で PIN を2回入力（手順3の SECRET_PIN と同じ数字）
　9. 設定タブ → GAS ウェブアプリURL を貼る →「保存して同期」→ 右上が「☁️ 0件」になれば接続OK
【初期データ】
　10. 設定タブ →「CSVインポート」→ spots-import-v10.csv を選ぶ → OK
　　 →「追加 529 件 ／ 除外 0 件 ／ 総数 529 件」と出れば完了（1回だけ行う）
【Places API（新規追加の検索を使う場合）】
　11. Google Cloud で Places API (New) を有効化 → APIキー発行
　　 （APIの制限：Places API (New) のみ。クォータと請求アラートを設定）
　12. 設定タブ → Places APIキー に貼って保存 →「✅ 設定済み」
【月1回の再取込（Google→アプリ）】
　Google Takeout で「保存済み」を書き出し → 設定タブの CSVインポートで CSV を複数選択。
　アプリに無いスポットだけが追加される（座標なしは未処理キューで補完）。
