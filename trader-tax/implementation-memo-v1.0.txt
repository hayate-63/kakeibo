§2　構成（引き継ぎメモ §2 への対応）
━━━━━━━━━━━━━━━━━━━━
・GAS URL／PIN は設定画面から localStorage に保存。キー名は trader_tax_gas_url／trader_tax_pin_v1（指定どおり）
・GAS の役割は CRUD のみ。計算はすべて HTML 内 <script id="tax-engine">（DOM 非依存の純関数。テストはこのブロックを抜き出して実行）
・通信はすべて POST（text/plain の JSON: {action, pin, rev, payload}）。PIN は URL に載せない
・PIN は GAS のスクリプトプロパティ APP_PIN に保存（シートには書かない）。全アクションで照合
・GAS URL 未設定時は端末内だけで動く「ローカルモード」（試用・オフライン表示用）。GAS と同じ変更処理（applyLocal）を手元で実行

■ DATA_REV（保存の競合検出）の方式
　家計簿とは別物として、本アプリ独自の方式で確定（2026-11-16 本人確認）。
　・スクリプトプロパティ DATA_REV（整数）。getAll で rev を返す
　・書込み時はクライアントの rev と一致する場合だけ実行し +1。不一致なら {status:'conflict'} を返す
　・アプリは conflict を受けたら getAll で最新を読み直し、「もう一度操作してください」と表示（自動再送はしない）
　・書込みは LockService で直列化

§3　データ（タブと列）
━━━━━━━━━━━━━━━━━━━━
trades: id, seq, tradeDate(約定日), settleDate(受渡日), account(一般/特定), code, name, side(買/売/数量調整), qty, price, amount, fee, realizedPnl, avgCostSnapshot, source, memo, createdAt
holdings: id, asOfDate(期首日), account, code, name, qty, costTotal, avgCost, memo, updatedAt
margin_positions: id, seq, openDate, account, code, name, side(買建/売建), qty, openPrice, openAmount, openFee, status(未決済/一部決済/決済済/現引/現渡), source, memo, createdAt
margin_settlements: id, seq, positionId, settleDate, deliveryDate, type(返済/現引/現渡), qty, closePrice, closeAmount, openFee, closeFee, interestPaid, interestReceived, lendingFee, gyakuhibuPaid, gyakuhibuReceived, divAdjPaid, divAdjReceived, otherCost, pnl, csvPnl, source, memo, createdAt
annual_reports: id, year, kind(上場分/特定信用分), proceeds, cost, net, lossAmount, dividends, divWithholdIncome, divWithholdResident, memo, updatedAt
dividends: id, date, code, name, amount, withholdIncome, withholdResident, account, memo, createdAt
carryover: year, filed, lossOverride, allocOverride(JSON), computedLoss, computedRemaining, expireYear, memo, updatedAt
settings: key, value, updatedAt（salaryIncome, deductionsIncome, deductionsResident, rateIncome, rateRecon, rateResident, yearBasis, divChoice_YYYY, accountGeneral, accountTokutei）

・金額は円の整数。単価（price/openPrice/closePrice）は 0.1円刻みの銘柄があるため小数可。平均取得単価は計算時に「取得費総額÷数量の円未満切上げ」で都度求め、明細には小数値も表示
・文字列・日付列は初期化時にプレーンテキスト書式（銘柄コード 130A 等や日付の自動変換を防ぐ）
・holdings は「期首保有（手入力が正）」を保持。現在保有は trades から再計算して表示。期首日以前の取引からの再計算と期首登録が食い違えば警告し、期首登録を採用
・期首建玉は margin_positions に通常の建玉として登録（建日は実際の建日）
・carryover は入力値（申告済みチェック・充当の手修正・発生額の手入力上書き）を保存し、計算結果は保存時のスナップショット列として併記

§5　CSV 取込（仮実装）
━━━━━━━━━━━━━━━━━━━━
・本人の指示どおり、実物サンプルが無いため「列対応表 CSV_CONFIG を分離した仮実装」。CSV_CONFIG.status = 'PROVISIONAL'
・CSV_CONFIG は tax-engine ブロックの先頭。列名は別名リスト（完全一致→部分一致の順）で探し、取引種別・預り区分は単語リストで判定
・画面には「列対応表は仮設定」のラベルと、読み取り結果ごとの「未検出の列」「ヘッダー行の中身」を表示するので、実物で何がずれたかがその場でわかる
・文字コード: BOM→UTF-8(厳密)→Shift_JIS の順に自動判定
・フロー: 読み取り→確認一覧（行ごとに登録／除外のチェック）→一括登録
・初期状態: 新規＝登録／重複候補＝除外／NISA＝対象外（変更不可）／特定預り＝除外（参考登録は可能だが計算対象外）／約定履歴中の信用行＝対象外（信用は信用決済明細CSVで取込）
・重複判定: 現物は 約定日＋銘柄＋取引種別＋数量＋単価＋預り区分（メモどおり）。信用は 決済日＋銘柄＋決済種類＋数量＋建単価＋決済単価＋預り区分
・SBI の CSV が新しい順の場合は古い順に並べ替えてから約定順（seq）を振る
・信用 CSV の決済損益列がある場合は、アプリ計算値と照合し、差異を確認一覧と警告に出す
・仮ルール（実物で要確認）: 金利・逆日歩・配当落調整金が符号なしの1列で出る想定で、建区分から支払／受取を振り分ける（costSignMode='bySide'。符号付きなら 'signed' に変更）

サンプル受領後の作業（第0ステップの残り）:
　1. 実物2種を読み込み、未検出の列・取引種別・預り区分の表記を CSV_CONFIG に反映
　2. 金利等の符号ルールと、建手数料が決済行ごとに按分済みかどうかを確認
　3. tests に実物ベースのケースを追加し、CSV_CONFIG.status を 'CONFIRMED' に変更

§6　計算仕様の実装内容（Muse の重点照合ポイント）
━━━━━━━━━━━━━━━━━━━━
(1) 現物（calcSpot）
・口座×銘柄ごとに 約定日→（期首登録を先に）→seq の順で処理
・買い: 取得費総額 += 約定代金＋手数料、数量 += 買付数量、平均単価 = 円未満切上げ（取得費総額÷数量）
・売り: 譲渡原価 = 平均単価×売却数量（取得費残を上限とする）。全量売却時は取得費残額をそのまま原価にする → 丸め残りが残高に積み上がらない
　取得費残 = 取得費総額 − 譲渡原価。平均単価は売却では再計算しない（次の買いで（残額＋買付）÷（残数＋買付数）で再計算）
・数量調整（分割・併合）: 取得費総額は不変、平均単価のみ再計算
・保有不足の売りは警告（期首保有の登録漏れや同日の約定順の確認を促す）
・計算対象は預り区分「一般」のみ（特定はモードTの報告書で計上、NISAは対象外）

(2) 信用（calcMargin）
・建玉ごと。決済1件ずつ精算。部分決済可。建手数料は決済行の値を使い、空欄の場合のみ数量で按分（最後の決済で端数を吸収）
・買建: 収入 = 返済売代金＋逆日歩受取＋金利受取、取得費等 = 新規買代金＋手数料(建・返済)＋買方金利＋その他 − 配当落調整金の受取 ＋ 配当落調整金の支払
・売建: 収入 = 新規売代金＋逆日歩受取＋金利受取 − 配当落調整金の支払 ＋ 配当落調整金の受取、取得費等 = 返済買代金＋手数料(建・返済)＋貸株料＋逆日歩支払＋その他
・配当落調整金は配当台帳に入れない（信用の画面にも注記）
・現引: 建玉を消し、取得費 = 建代金＋諸経費（逆日歩・調整金の受取は控除）の現物買いとして現物計算に渡す（損益なし）
・現渡: 保有現物を建値で譲渡したものとして現物計算に渡す（原価は現物の平均単価）。現物の売却明細に「現渡」として表示
・課税年は決済の受渡日（設定で約定日基準に変更可）。未決済建玉は課税年に含めず別表示

(3) 損益通算・繰越（computeYear）
　① 譲渡所得等の内部通算: G現物＋G信用＋T上場分の差引＋T特定信用分の差引
　② 譲渡損失が残れば「申告分離」を選んだ配当とだけ通算（申告不要・総合課税の配当とは通算しない）
　③ 前年までの繰越損失を古い年から充当。控除先は 譲渡所得等 → 分離配当 の順。使用可能期間は発生年の翌年〜3年後
　④ なお残った譲渡損失を本年の繰越損失として発生
　・連続申告: 繰越損失を使う年に、発生年〜前年のどこかに「申告済み」チェックが無ければ警告（計算はそのまま行う）
　・本年分で控除しきれず期限切れになる損失は「失効」と警告。ホームでも失効が近い年を表示
　・手修正: 充当額（年×発生年ごと）と発生額の上書きができ、使った場合は警告で明示

(4) 税額
・課税対象は 譲渡所得等 と 分離配当 をそれぞれ1,000円未満切捨てして合計
　（申告書第三表で区分ごとに切り捨てるため。T1〜T6 の範囲では「合計してから切捨て」と結果は同じ）【Muse確認依頼②】
・所得税 = 課税対象×15%、復興 = 所得税×2.1%、国税 = (所得税＋復興) の100円未満切捨て
・住民税 = 課税対象×5% の100円未満切捨て
・精算 = 国税 − 源泉所得税 ＋ 住民税 − 源泉住民税（申告不要を選んだ配当の源泉は精算に使わない）
　※メモ T2 の期待値（還付 20,372）に合わせ、国税は100円未満を切り捨ててから源泉と精算している。
　　実際の申告書は「所得税及び復興特別所得税の額 − 源泉徴収税額」を出してから納付額だけを100円未満切捨て（還付は1円単位）なので、
　　還付の年は実際の還付額と最大99円ほどずれる。目安として許容と判断した【Muse確認依頼③】
・配当の源泉（台帳入力時の目安）: 所得税 = 配当×15.315% の円未満切捨て、住民税 = 配当×5% の円未満切捨て（計算書の実額で上書き前提）

(5) 配当方式比較
・3方式（申告不要／申告分離／総合課税）を同じ繰越残から計算し、国税・住民税・源泉の精算・納付/還付・税負担の総額（申告不要は源泉税額を含む）・翌年繰越を並べる
・総合課税: 給与所得見込み・所得控除合計（所得税/住民税）から、配当を加えた場合の増分を速算表で計算。配当控除は所得税10%（課税総所得1,000万超部分は5%）、住民税2.8%（同1.4%）。調整控除などは省略した目安
・推奨: 譲渡損失がある年は「申告分離」（通算で還付＋残りの繰越）。それ以外は税負担の総額が最小のもの（同額なら申告不要）。給与所得見込みが未設定なら総合課税は推奨しない
・所得税と住民税で方式を分けられない点、合計所得金額への影響を画面に明記
・方式は年ごとに1つとして扱う（銘柄・支払ごとの選択はv1.0では未対応）

(6) 配当の拾い方
・報告書（モードT）の配当等の額＋配当台帳（一般）
・台帳の「特定」受取分は、同じ年の報告書に配当が入力されていれば自動で除外し警告（二重計上防止）。報告書が未入力の年中だけ見込みとして使う

(7) 申告要否の目安（20万円）
・給与以外の所得（譲渡所得等のプラス分＋申告する配当）が20万円以下なら所得税の申告不要の目安を表示。
　住民税の申告は別途必要・繰越を使う/繰り越すなら申告必要の例外を必ず併記

§10　v1.0 で未対応・既知の制約
━━━━━━━━━━━━━━━━━━━━
・CSV の列対応は仮（§5）
・受渡日の初期値は「約定日＋2営業日（土日と12/31〜1/3を除外）」。祝日は考慮しないので手で直す
・同じ日の約定順は seq（入力順／CSV の行順）に従う。CSV に時刻が無い場合、同じ日の売買の順序が実際と違うと平均単価が変わることがある（保有不足なら警告）
・総合課税の比較は目安（調整控除・定額減税・各種控除の詳細は省略）
・確定申告書の作成、e-Tax 送信、SBI 以外の CSV、FX・先物・暗号資産は範囲外（メモ §10 のとおり）
