（「統合家計簿アプリ v2.0」）だけで、index-v5.1.html と

- LOG_HEADERS: v2.0 に GAS が無いので確認不可。
  → 対策: 新規ログは「loadAll で返ってきた既存ログ1件目の
    キーを全部 '' で用意 → 本連携の項目を上書き」で組み立てる。
    v5.1 にメモに無い列があっても、列が欠けた行にはならない。
- evaluateEntry: v2.0 の引落日計算は設計メモと同じ
  （締め日超過で +1ヶ月、payMonthOffset、payDay）。
  ただし v2.0 には休日調整（adjust）が無い。v5.1 の
  adjust の値と休日の定義は未確認（下記 C-3）。
- DATA_REV: v2.0 には rev／baseRev が無い（POST は投げっぱなし）。
  設計メモの v3.0.2 の記述（status: saved / conflict /
  unauthorized / busy）を前提に実装した。
- Config キー: v2.0 は actualBalance のみ。dodai_* は無い。

→ お願い: index-v5.1.html と GAS_v3.0.2.txt をリポジトリに
  置いてもらえれば、§0 の4点と下記 C の要確認項目を照合する。

B. §6 recalculateAllLogs の発動条件 ―― 【v2.0 では戻る。v5.1 は要確認】
================================================================
v2.0 では recalculateAllLogs() が
  起動時（initApp）／クラウド同期後（syncFromCloud）／
  明細追加（commitNewEntry）／明細削除（deleteLogItem）／
  サンプル投入・全削除・CSV取込
のたびに全明細へ走り、usageCat / budgetCat を
evaluateEntry の辞書判定で上書きする。
つまり v2.0 のままなら、本連携で直接セットした
budgetCat（例「変動費（ガジェット）」）は、家計簿アプリを
開いて同期した時点で辞書判定に戻る（メモ＝商品名が辞書に
無ければ「その他（要確認）／変動費（その他）」）。
v5.1 で発動条件が変わっているかは未確認。v1.0 は設計どおり
直接セット方式。v5.1 でも戻るなら、家計簿側で
「usageCat/budgetCat が入っている行は再計算で上書きしない」
等の対応が必要。

C. 設計メモと照合が必要な前提（v5.1 で確認してほしい点）
================================================================
1. 家計簿 GAS への POST の形
   UrlFetchApp で text/plain の JSON
   { pin, baseRev, logs } を送っている（action 無し）。
   「logs だけ送ると logs シートだけ上書き」される前提。
   他シートまで空で上書きする実装なら絶対に使わないこと。
2. loadAll の各配列のキー名
   - budget: budgetCat / monthly / bonusAdd / bonusMonths
     （bonusMonths は "6,12" / [6,12] / "2026-06" 形式を許容）
   - budgetMonthly: 対象月は ym / month / yearMonth /
     targetYM のどれか、budgetCat、amount
   - categories: name / mode / bigCat / closeDay /
     payMonthOffset / payDay / adjust / active
   - config: [{key, value}] 配列でもオブジェクトでも可
3. 休日調整: adjust が "next"（または「翌」「後」を含む）なら
   次の平日、"prev"（または「前」）なら前の平日。休日＝土日＋
   国民の祝日（振替休日・国民の休日を含む、計算で算出）。
   年末年始（12/31・1/2・1/3）は休日に含めていない。
   v5.1 と違えば calcPayDate_ / jpHolidays_ を合わせる。
4. 1日予算（renderDailyBudgetBanner）: 定義未確認のため
   「変動費残金 ÷ 今月の残り日数（今日を含む）、切り捨て」
   で仮実装。違えば client の calcA() を直す。
5. absAmount が無いログは |amount| を使う。useYM が無いログは
   useDate → date から算出（ISO 文字列は JST で解釈）。
6. 実残高 0 判定: Config に actualBalance が無い時も 0 扱い
   → ログ算出残高に切り替え。

================================================================
1. Google ドライブで新規スプレッドシートを作成（名前は任意、
   例「ほしいもの帳DB」）。
   メニュー「拡張機能 → Apps Script」を開き、コード.gs の
   中身を全部消して gas-v1.0.txt を貼り付けて保存。

     SECRET_PIN    = ほしいもの帳のパスワード（英数字・記号4〜64文字）
     HOUSEHOLD_PIN = 家計簿の PIN
3. エディタ上部の関数で setup を選び「実行」（初回は権限の承認）。
   items / categories（13件＋対応表）/ tags / settings
   シートができ、DATA_REV=0 が入る。
   （任意）testSummaryDummy / testPayDate を実行すると
   ログに計算結果が出る（家計簿へは書き込まない）。
4. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」
   実行ユーザー: 自分 ／ アクセスできるユーザー: 全員
   → 発行された …/exec の URL を控える。
   ※ 以降 GAS を直したら「デプロイを管理 → 編集 → 新バージョン」
     で URL を変えずに更新する。
5. index-v1.0.html の先頭近くの
     const GAS_URL = 'https://script.google.com/macros/s/XXXXXXXX/exec';
   を 4 の URL に差し替え、Netlify（家計簿とは別サイト）へ
   index.html としてデプロイ。
6. iPhone でサイトを開きパスワードでログイン → 設定タブ:
   家計簿連携に家計簿 GAS の URL を入れて「保存」、
   「連携する」を ON。計算タブで家計簿の値（変動費残金・
   防衛資金枠）が出ることを確認する。
   → 家計簿アプリの表示と数字が一致するか必ず見比べる（C-4 の
     1日予算も）。
7. Safari の共有 →「ホーム画面に追加」。

※ 家計簿への書き込み（買った！）は、最初は少額のテスト商品で
  1回試し、家計簿アプリ側で明細が出ること・他の明細が消えて
  いないこと・購入済から「家計簿の明細も消す」で消えることを
  確認してから本運用に入ること。

E. 実装の要点
================================================================
- 通信は全て POST（text/plain JSON）で { action, pin, ... }。
  PIN を URL に載せない。家計簿 PIN はクライアントに一切出ない。
- 自前DB: DATA_REV ＋ baseRev で競合検出、LockService で直列化
  （取れなければ busy）、書く直前に bk_<シート>_<日時> の
  隠しシートでバックアップし 10世代でローテーション。
- 空上書きガード: (1) クライアントはサーバーから読み込めるまで
  保存しない（前回キャッシュ表示中は保存不可）。(2) GAS は
  2件以上あるシートを0件にする保存を拒否。(3) 削除は1件ずつ
  しか減らせない。(4) 家計簿へ送る logs は「取得件数＋1」
  「取得件数−1」以外なら送らない。家計簿が0件で返ったら送らない。
- 買った！: GAS の purchase が「自DBの rev 確認 → 家計簿
  loadAll → 新規1件を足して POST（conflict は loadAll から
  1回だけやり直し）→ 成功時のみ items 保存（householdLogId
  付き）」を1回のロック内で行う。家計簿側が失敗したら items は
  書かず、クライアントはシートを開いたまま赤バナーを出す。
  （家計簿 OK・自DB保存だけ失敗という稀なケースは、バナーに
   作成済みの明細 id を出す）
- 削除: householdLogId があれば「家計簿の明細も消す／
  ほしいもの帳だけ消す／キャンセル」を出す。家計簿側に既に
  その id が無い時は自DBだけ消して、その旨トーストに出す。
- 家計簿サマリーの前回値は GAS（HH_LAST）と端末の両方に保持。
  計算タブは古い値でも「○月○日 ○時 時点の値を表示中」付きで
  表示。欲しい物カードの「¥→¥」と詳細の影響行、タグ帯は
  このセッションで取得に成功した時だけ出す（ラベルが無いため）。
- ?add=<URL>: 起動時に検出してすぐ replaceState で消し、
  ログイン・同期後に読み取り → 確認カードを開く。
- URL 読み取り: 短縮URLは 3xx を自前で辿る。JSON-LD（@graph
  内も探索）→ OGP/meta → title の順。文字コードは
  ヘッダー／meta から判定（楽天の EUC-JP 等）。Amazon は
  /dp/ASIN に正規化しタイトルの「Amazon.co.jp:」を除去。
  取れなくても失敗にせず、手入力の確認カードへ。
- タグ絞り込みは複数選択時 AND（全部のタグを持つ商品）。
- PIN 照合は10回失敗で10分ロック（CacheService）。

     busy → 再試行 → 成功の流れを確認。失敗時はシートと入力が
     残ることも確認）
