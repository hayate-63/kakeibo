A. 第0ステップ（家計簿コードの確認）の結果
================================================================
【結論】家計簿 GAS v7.0 のコードは、このリポジトリ
（hayate-63/kakeibo の全ブランチ）にも、受け取ったファイル
にも無かったため、v7.0 とは照合できていない。
→ 引き継ぎメモ §0 の指示「ほしいもの帳の連携実装があれば、
  その方式に揃える」に従い、ほしいもの帳 GAS v1.0.1
  （家計簿 index-v5.1 / GAS v3.0.2 と照合済み）と同じ方式で実装した。

1. loadAll の形式（ほしいもの帳の照合結果＝GAS v3.0.2 の形式）
   - 呼び方: GET <家計簿URL>?action=loadAll&pin=<家計簿PIN>
   - 応答: { status: "ok"（または "success"）, rev, logs[], config, ... }
     PIN 違いは { status: "unauthorized" }
   - rev は応答の rev。記録帳は家計簿へ書き込まないので、
     家計簿の rev は使わない（記録帳の rev とは無関係）
2. 土台（エース預金）の残高・防衛枠
   - 家計簿側の集計値（防衛枠）は v3.0.2 の loadAll には無い
     → 【自前計算になった】残高だけ取得し、防衛枠は §4 の定義
       MIN（残高, 1,000,000）を記録帳 GAS で計算している。
   - 残高の取り方（家計簿 calculateDodaiMetrics と同じ。
     ほしいもの帳 computeSummary_ の基準B と同一のロジック）:
       config.actualBalance（実残高）が 0 以外 → その値
       0 の時 → dodai_start_balance ＋ Σ（−amount）
         対象: category が エース預金／エース預金（引出）／
         デイトレ貯金、useYM が dodai_start_ym（既定 2026-10）
         〜今月の明細
   - コードの場所: gas-v1.0.txt の extractBalance_()（1関数に
     まとめてある）。v7.0 で形式が違えば、ここだけ直せばよい。
3. ほしいもの帳の連携方式に揃えた点
   - 家計簿 GAS の URL は記録帳の settings シートに保存
     （設定タブで登録・変更。ハードコードしない）
   - 家計簿の PIN は記録帳 GAS のスクリプトプロパティから使い、
     クライアント（画面）には一切出さない
   - 家計簿のスプレッドシートは一切開かない（openById 等なし）
   - 家計簿へは loadAll（読み取り）しか呼ばない。書き込みの
     コード自体が無い

B. 要確認（Muse／本人に判断してほしい点）
================================================================
B-1【重要】家計簿 v7.0 との照合
   v7.0 のコード（GAS と index）を受け取れれば、次を確認して
   必要なら extractBalance_ を直す（v1.0.1 で対応）:
   (a) GET ?action=loadAll&pin= で今も読めるか（POST 専用に
       変わっていないか）
   (b) 応答の status が "ok"／"success" か、logs・config の形
   (c) 土台残高・防衛枠の集計値が応答に含まれるようになって
       いるか → 含まれるなら「家計簿の値をそのまま使う」に
       切り替える（§0 の方針。二重計算しない）
   (d) エース預金関連のカテゴリー名・dodai_* キーが同じか
   ※ v7.0 デプロイ後の実機確認で、記録帳の「土台残高」と
     家計簿アプリの表示が一致するかを必ず見比べること
B-2 防衛枠の上限
   §4 どおり MIN（残高, 1,000,000）の固定値で計算している。
   ほしいもの帳は家計簿の dodai_target を上限に使っている。
   家計簿の dodai_target が 100万円以外だと、家計簿の表示と
   防衛枠の数字がずれる（バーの分母＝記録帳の目標額は別設定）。
B-3 家計簿の PIN
   デプロイ手順どおり SECRET_PIN を家計簿と同じにすれば、
   それを家計簿の PIN として使う。スクリプトプロパティ
   HOUSEHOLD_PIN を入れた場合はそちらを優先。
   設定タブで記録帳のパスワードを変えると、変更前の値を
   自動で HOUSEHOLD_PIN に残す（家計簿連携が切れないように）。
   家計簿側の PIN を変えた時は HOUSEHOLD_PIN を手で直す。
B-4 パスワードの「この端末に記憶する」
   スポット帳 v2.0.1 と同じ仕組みをログイン画面に付けた
   （既定は OFF。ログアウトで消える）。仕様に明記は無いので、
   不要なら外す。
B-5 資金の取得タイミング
   「ホーム表示時」はタブを切り替えるたびに家計簿を呼ぶことに
   なるため、自動取得は 60秒に1回まで（再読込ボタンは毎回取得）。
B-6 検証の必須項目
   仕様に無いので、日付・銘柄・結果 を必須にした
   （エントリー根拠・価格・損益・メモ・英語3行は任意）。
B-7 RR の持ち方
   小数2桁に丸めて trades.rr に保存し、平均RR はその保存値の
   平均。表示も小数2桁（例: 1:2.50）。
B-8 テーマ色
   データモデル（settings）にあるため、設定タブに6色の選択を
   置いた。画面仕様には無いので、不要なら外す。
B-9 保存の安全装置（ほしいもの帳と同じ考え方）
   1回の保存で減らせる件数は1件まで（読み込み失敗時の
   空上書き防止）。保存の直前にシートを bk_<シート名>_<日時>
   の隠しシートに複製（シートごとに10世代）。

C. 実装の要点（引き継ぎメモとの対応）
================================================================
§2 DB: シートと列（英語キー）
  practice   id, date, lens, symbol, jumpDate, candle, after3d, note, createdAt
  trades     id, date, symbol, basis, entryPrice, takeProfit, stopLoss, rr,
             result, pnl, memo, enWhat, enWhy, enNext, createdAt
  conditions date, sleepOk, noFatigue, calm, judge
  fund       balance（土台残高）, defenseFund（防衛枠）, target（目標額）,
             fetchedAt（取得時刻）
  milestones id, period, content, targetAmount, done, sort
  settings   key, value（householdUrl / householdEnabled / themeColor）
  ※ 全セルを書式なしテキストで書く（銘柄コード 7203 や日付が
    勝手に数値・日付に変わらないように）
  ※ PIN はシートに置かない（スクリプトプロパティ SECRET_PIN）
保存方式（家計簿方式）:
  - 通信は全て POST（text/plain JSON）{ action, pin, ... }。
    PIN を URL に載せない
  - loadAll で全件取得、save は { baseRev, tables:{…} } で
    送ったシートを全件上書き。rev 不一致は conflict を返して
    何も書かない。LockService で直列化（取れなければ busy）
  - fund の取得キャッシュの書き込みでは rev を進めない
    （ホームを開くたびに他端末が conflict にならないように）
  - RR と判定（ok/watch）はクライアントの値を使わず、GAS が
    保存時に計算し直して持つ
§3 資金カード:
  - 記録帳 GAS の fund アクションが家計簿 loadAll を呼ぶ
  - 成功: 防衛枠・バー（防衛枠÷目標額）・残高・取得時刻（最新）
  - 失敗: 前回値に「11月20日 13時 時点の値です（取得に失敗: 理由）」
    の黄色い帯を必ず付ける。黙って現在値として出さない
  - 未取得の前回値（起動直後など）も「時点」の帯付きで出す
  - 連携 OFF: 「連携が OFF です」
  - 家計簿 URL は https://script.google.com/ で始まるものだけ
    受け付ける（家計簿の PIN を他のサーバーへ送らないため）
§4 計算: 件数（skip 含む）、勝率 win÷(win+lose)（0なら「−」）、
  平均RR（RR 空欄は除外）、防衛枠、Phase 0 ゲート3項目
  （✅／⬜ で表示。自動では何もしない）
§5 コンディション: 1日1件（日付キー）。ホーム最上部で3つの
  チェック→保存（当日分があれば上書き）。未入力の日は
  「今日のコンディション 未チェック」。検証フォームの上に
  当日の判定（ok／watch／未チェック）を表示
§6 画面: 4タブ。練習は 10件到達で「🎉 10件到達 → 次のレンズへ」。
  検証フォームのエントリー前チェックは警告のみで保存可・保存しない。
  損益は iPhone の数字キーボードにマイナスが無いので「±」ボタンを付けた。
  CSV は BOM 付き UTF-8（Excel で文字化けしない）、日本語見出し
§7 共通仕様: PIN は type="password"・英数字＋記号4〜64文字
  （自動大文字・自動修正オフ）。SECRET_PIN 未設定なら全て拒否。
  10回失敗で10分ロック。保存は直列化キューで送り、保存中は
  スピナー、成功はトースト、失敗は消えない赤バナー＋理由＋
  再試行ボタン。status が "saved" の時だけ成功扱い。
  失敗時はフォームを閉じない（入力が残る）。conflict の時は
  「再読込してもう一度保存」ボタン（再読込した最新データの上に
  同じ変更を積み直す。上書きはしない）

D. デプロイ手順（本人がやること）
================================================================
1. Google ドライブで新規スプレッドシート「記録帳DB」を作成。
   メニュー「拡張機能 → Apps Script」を開き、コード.gs の
   中身を全部消して gas-v1.0.txt の中身を貼り付けて保存。
   （既存の家計簿などの本には混ぜない）
2. 「プロジェクトの設定（歯車）→ スクリプト プロパティ」に追加:
     SECRET_PIN = 家計簿と同じ PIN
   （家計簿の PIN と変えたい場合は、SECRET_PIN を記録帳の
    パスワードにして、HOUSEHOLD_PIN = 家計簿の PIN も追加）
3. エディタ上部の関数で setup を選んで「実行」（初回は権限の承認）。
   practice / trades / conditions / fund / milestones / settings
   シートができ、マイルストーン4件（2026年12月〜2028年1月）と
   目標額 1,000,000 が入る。実行ログに「SECRET_PIN も設定済み」
   と出ることを確認。
4. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」
   実行ユーザー: 自分 ／ アクセスできるユーザー: 全員
   → 発行された …/exec の URL を控える。
   ※ 以降 GAS を直したら「デプロイを管理 → 鉛筆（編集）→
     バージョン: 新バージョン → デプロイ」で URL を変えない。
5. index-v1.0.html の先頭近く（<script> の直後）の
     const GAS_URL = "https://script.google.com/macros/s/XXXXXXXX/exec";
   を 4 の URL に差し替え、Netlify に新規サイトを作って
   index.html（＝差し替えた index-v1.0.html）と icon-180.png を
   同じ場所に置く。（zip の「Netlify用」フォルダをそのまま使える）
   ※ 差し替え忘れても、初回のログイン画面で URL を入れられる。
6. iPhone の Safari でサイトを開き、パスワードでログイン →
   Safari の共有 →「ホーム画面に追加」（名前は「記録帳」）。
7. 設定タブ「家計簿連携」に家計簿 GAS の URL を入れ、
   「連携する」を ON にして保存 → ホームの資金カードで
   土台残高が出ることを確認。家計簿アプリの表示と見比べる。
   （前提: 家計簿 v7.0 がデプロイ済みであること。未デプロイ
    なら、先に家計簿 v7.0 をデプロイしてから確認する。
    取れない時は、資金カードの黄色い帯に理由が出る）

E. 自己検証の結果（§10）
================================================================
実行: cd test && node run-test.js（Playwright の Chromium を使用）
結果: 131 項目すべて PASS（GAS 単体 66 ＋ ブラウザ通し 65）

1. CRUD とリロード後の再表示
   - 練習: 追加（銘柄・気づきの必須チェック）／編集／削除、
     列の値（レンズ volume・跳ねた日・足の形・その後3日・作成日時）
   - 検証: 追加5件／編集（負け→勝ち）／削除
   - コンディション: 保存／当日分の上書き
   - マイルストーン: 追加／編集／達成フラグ／並び替え（↑）／削除
   - ページを再読み込み（記憶したパスワードで自動ログイン）
     → コンディション・チェック欄・進捗・練習一覧・検証一覧・
       マイルストーンの達成フラグがそのまま出ることを確認
2. 集計の検算（画面の表示で確認）
   データ: A 勝ち RR3（1000/1300/900）、B 負け RR1、C 見送り
   （価格なし）、D 勝ち RR2（500/520/510）、E 見送り（価格が
   1つだけ）
   - 件数 5件（見送り2件を含む）              → 一致
   - 勝率 2÷(2+1) = 66.7%（見送りは分母外）   → 一致
   - 平均RR (3+1+2)÷3 = 2.00（C・E を除外）    → 一致
   - B を勝ちに編集 → 勝率 3÷3 = 100.0%        → 一致
   - Phase 0 ゲート: 検証100回 ⬜（4/100）、勝率 ✅、平均RR ✅
   - GAS 単体: RR 3.00/1.00/2.00/2.50（カンマ付き価格）、
     損切り幅0・価格不足は空欄、クライアントが送った RR は無視
3. コンディション判定
   - 全ON → ok（参戦可）、1つOFF → watch（今日は監視のみ）
   - 当日分の上書き後もシートは1件（upsert）
   - クライアントが送った judge は無視して GAS が判定
   - 同じ日付の2件目は error
   - 検証フォームに当日の判定（watch）が出ること
4. 資金（家計簿 API のモック）
   - 連携 OFF →「連携が OFF です」（家計簿を呼ばない）
   - actualBalance 640,000 → 残高 ¥640,000・防衛枠 ¥640,000・
     バー 64.0%（目標 100万）
   - 再読込ボタン → 1,250,000 → 防衛枠 ¥1,000,000・バー 100.0%
   - 目標額 200万 → バー 50.0%
   - actualBalance=0 → 明細から 300,000＋50,000−10,000 = 340,000
     （開始月より前・来月以降・他カテゴリーは除外）
   - 取得失敗（HTTP 500／接続エラー／HTML 応答／家計簿 PIN 違い）
     → error ＋ 前回値。画面は「11月20日 13時 時点の値です
       （取得に失敗: 家計簿 GAS が HTTP 500 を返しました）」と
       前回値を表示。再読み込み後も同じ
   - 家計簿への呼び出しは全て GET の loadAll（書き込みなし）
   - 家計簿 URL が script.google.com 以外なら保存を拒否
5. SECRET_PIN 未設定
   - auth／loadAll／save／fund／changePin の全てが unauthorized
     （空・"1234"・"undefined"・"null" のどれでも）。空文字の
     SECRET_PIN も同じ。changePin で PIN を作ることもできない
   - setup のログに「SECRET_PIN が未設定です」と出る
6. baseRev 不一致
   - GAS 単体: 古い baseRev／baseRev なし → conflict、シートも
     rev も変わらない。ロックが取れない → busy
   - 画面: 別端末が保存した後に保存 → 赤バナー「他の端末で
     更新されています」、別端末の記録は残り、こちらは未保存。
     「再読込してもう一度保存」→ 両方残る
7. その他
   - 保存中のスピナー表示、通信失敗で消えない赤バナー
     （3秒後も表示）＋再試行 → 成功でバナーとフォームが閉じる
   - 失敗時はフォームと入力内容が残る
   - 一度に2件以上減る保存・3件→0件の保存は拒否、1件ずつの
     削除は通る、保存前に bk_ 隠しシートを作る
   - 10回失敗で10分ロック、PIN 変更（3文字・全角は拒否）
   - CSV（BOM・日本語見出し・結果は 勝ち/負け/見送り）
   - スマホ幅（390px）で横スクロールなし、JS エラーなし
8. 検証中に見つけて直した不具合
   - 赤バナーの「再試行」から保存に成功した時、フォームが
     開いたままだった → 成功したらそのフォームを閉じるように修正
   - 再読み込み後、コンディションのチェック欄が保存済みの値で
     なく全部 OFF で出ていた → 保存済みの値に合わせるように修正

検証できていないこと:
   - 本物の家計簿 GAS（v7.0）との通信（コード未入手。B-1）
   - 本物の Google 環境での動作（この検証環境からは Google に
     接続できない。デプロイ後に本人が実機で確認）

F. 既知の制限
================================================================
- 単一HTMLのため Service Worker は無い（ホーム画面追加は可、
  オフライン起動は不可）。通信できない時は赤バナーで再試行。
- 「今日」は端末の日付で決める（日本時間の端末前提）。
  日付が変わった後にアプリへ戻ると、コンディションは新しい日の
  分に切り替わる。
- iOS のホーム画面アプリでは CSV のダウンロードが新しい画面で
  開くことがある（共有ボタンから保存）。
